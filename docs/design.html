Design & build plan · v1

Photo PDF

A small installable web app. You pick photos from the gallery on an iPhone or Android phone, put them in order, and share them as one PDF through the system share sheet. All processing happens on the device and nothing is uploaded.

03 · Architecture

No backend: a static app that does all its work in the browser

The build output is a folder of static files. A service worker caches them, so the app opens and works offline after the first visit.

Source layout

  • src/main.tsxMounts React and registers the service worker, with auto-update.
  • src/App.tsxScreen state machine: start → arrange → creating → ready.
  • state/images.tsReducer with add, remove, rotate, move and clear. Frees thumbnail URLs.
  • lib/readImages.tsDecodes picked files into 360 px thumbnails and skips files it can't read.
  • lib/renderPage.tsCanvas step: applies rotation, downscales, outputs JPEG on white.
  • lib/buildPdf.tspdf-lib, loaded on demand. Page size, orientation and placement.
  • lib/share.tsWeb Share with a File, or a download fallback.
  • lib/settings.tsPage mode stored in localStorage.
  • i18n/cs.ts and en.ts, with Czech plurals via Intl.PluralRules.
  • components/StartScreen, ArrangeScreen, SortableTile, SettingsSheet, ProgressDialog, ReadyScreen, InstallHint, Toast.

Data model

type Item = {
  id: string
  file: File               // original, kept until PDF is built
  thumbUrl: string         // object URL of 360 px preview
  width: number; height: number
  rotation: 0 | 90 | 180 | 270
}
type Settings = { pageMode: 'a4' | 'fit' }  // default 'a4'

PDF pipeline, run once per image in order

  1. DecodeLoad the file into an <img> from an object URL. The browser applies the EXIF orientation, so photos aren't sideways.
  2. Rotate and downscaleDraw onto a canvas, applying the user's rotation, with the long edge at most 2000 px. Fill with white first so transparent PNGs come out right.
  3. Compresscanvas.toBlob('image/jpeg', 0.8) gives roughly 250–600 KB per page.
  4. EmbedpdfDoc.embedJpg(bytes). The JPEG goes into the PDF as is, with no second re-encode.
  5. PlaceA4: 595.28 × 841.89 pt, turned landscape when the image is wider than tall. Scale = min(page ÷ image) on both axes, centered. Fit to image: page takes the image's ratio, long edge 841.89 pt.
  6. Free memorySet the canvas width to 0 and drop references before the next image. This matters on iPhone.

The result is new File([bytes], name, {type: 'application/pdf'}), which goes to navigator.share({ files: [file] }) when navigator.canShare accepts it.

Dependencies

  • react, react-domUI
  • pdf-libBuilds the PDF. Loaded only when you tap Create PDF.

The share sheet only opens straight from a tap. Building a PDF takes a few seconds, and by the time it finishes the browser no longer treats the work as part of the original tap. That's why creating and sharing are two separate taps: Create PDF, then Share.

05 · Build plan

Seven phases, each ending in something testable on a phone

  1. PHASE 1

    Scaffold and installability

    • Vite + React + TypeScript project
    • vite-plugin-pwa: manifest, display: standalone, service worker
    • App icon SVG → 192, 512, maskable and 180 px apple-touch icons
    • iOS meta tags, safe-area insets, light/dark tokens

    Done when: it installs on both phones and opens offline.

  2. PHASE 2

    Pick and show

    • Start screen and file input
    • Thumbnail generation, skipping unreadable files
    • Arrange grid with page numbers, Add, Remove and Clear

    Done when: 30 photos from an iPhone show up in the order picked.

  3. PHASE 3

    Edit

    • dnd-kit sortable grid, long-press (200 ms) touch sensor
    • Rotate in 90° steps, shown live on the tile
    • Scrolling still works while dragging is possible

    Done when: reordering works with one thumb on both phones.

  4. PHASE 4

    PDF generation

    • renderPage: rotation, 2000 px downscale, JPEG 0.8
    • buildPdf: A4 with automatic orientation, or Fit to image
    • Progress dialog and settings sheet

    Done when: a 20-photo PDF is under ~10 MB and pages look right.

  5. PHASE 5

    Share and save

    • Ready screen with an editable file name
    • Web Share with the file, download fallback
    • Error messages for failures and cancelled shares

    Done when: the PDF reaches Mail and Messages on both phones.

  6. PHASE 6

    Language and install prompts

    • Czech and English dictionaries, picked from navigator.language
    • iOS install hint, Android Install button
    • "New version available" notice from the service worker

    Done when: a Czech phone shows Czech everywhere, plurals included.

  7. PHASE 7

    Test and ship

    • Real devices: Safari, installed iOS app, Chrome, installed Android app
    • Memory test with 50 photos on an older iPhone
    • npm run build → dist/, README, server config example

    Done when: it runs from your server over HTTPS.

06 · Deploy

Your server: static files over HTTPS

Home-screen install and the service worker need HTTPS. Copy dist/ to the web root and set these headers so updates reach users.

# nginx example (deploy/nginx.conf.example)
location = /sw.js                { add_header Cache-Control "no-cache"; }
location = /manifest.webmanifest { add_header Cache-Control "no-cache";
                                   types { application/manifest+json webmanifest; } }
location /assets/                { add_header Cache-Control "public, max-age=31536000, immutable"; }
location /                       { try_files $uri /index.html; }

To test on a phone during development, run npm run dev -- --host with HTTPS enabled, or deploy a preview build to your server. iOS only allows service workers on a trusted certificate.

Details I filled in myself

I'll use these unless you change them.

  • App name: "Photo PDF"Used for the home screen label in both languages. The icon is the blue page stack shown above.
  • File name: photos-YYYY-MM-DD-HHmm.pdfCzech devices get fotky-…. Editable before sharing.
  • No page marginsWhite bands appear only where the image's proportions differ from A4.
  • Compression: 2000 px long edge, JPEG quality 0.8Sharp on screen and in print, about 0.3–0.6 MB per page.
  • Images are not kept between sessionsClosing the app clears the selection. Nothing is stored except the page-size setting.
  • Served from the domain rootA sub-path like /pdf/ is one config value if you need it.
  • TypeScriptPlain React + Vite with TS types. Switching to JS is easy if you prefer it.
  • Not included: Android share targetSharing photos into the app from the gallery is Android-only. It could be added later.
